# 飞书长连接与代理支持设计规格

日期：2026-10-02  
状态：用户已确认  
设计路径：Superpowers Architectural

## 1. 背景与目标

HotNews 当前通过飞书 HTTP webhook 接收群消息。个人使用环境中的机器长期在线，但只能通过本机代理访问外网，因此改为飞书长连接模式，彻底移除公网回调入口。

本次改造的成功标准：

- 无需公网域名、端口映射或内网穿透即可接收飞书事件。
- 长连接成为唯一的飞书事件入口，不保留 webhook 回退模式。
- 使用 `FEISHU_WS_PROXY` 或标准代理环境变量访问飞书。
- 继续只处理群聊中明确 `@机器人` 的文本消息。
- 保留现有 SQLite 幂等、订阅解析、定时搜索、飞书推送和本机管理页面。
- 代理中断并恢复后，应用可以自动恢复长连接。
- 配置、日志、诊断结果和管理页面均不泄露凭据或临时连接 URL。

## 2. 方案选择

### 2.1 采用方案

使用官方飞书 Python SDK 处理长连接协议、心跳、事件分发和基础重连，并增加一个项目内隔离的代理兼容层。兼容层只负责把解析后的代理地址传入 SDK 使用的 WebSocket 连接函数。

由于官方 Python SDK 当前没有公开的长连接代理参数，项目将：

- 固定经过测试的 `lark-oapi` 与 `websockets` 兼容版本；
- 将所有私有接口依赖限制在单个兼容模块内；
- 启动时检查 SDK 版本和目标调用签名；
- 在兼容性不满足时失败关闭，并提示升级项目适配代码；
- 用单元测试固定代理参数注入行为。

这适合单机器人、单进程、个人长期在线的部署方式，并把 SDK 私有接口风险限制在清晰边界内。

### 2.2 未采用方案

- **自行实现飞书长连接协议**：虽然能完全控制代理，但需要维护端点发现、Protobuf 帧、心跳、确认和重连协议，协议风险与维护成本过高。
- **Node.js 长连接侧车**：Node SDK 有公开的代理环境变量支持，但会引入第二个运行时、独立进程和进程间通信，不适合当前轻量部署目标。

## 3. 总体架构

应用保持一个常驻 Python 进程，运行长连接、管理页面和飞书发件箱工作器。Codex Scheduled Task 仍按既有设计处理待办事件、到期订阅和热点搜索。

```text
飞书长连接
  │ im.message.receive_v1
  ▼
SDK 事件适配器
  │ 结构化、过滤、幂等入库
  ▼
SQLite ─────────────── Codex Scheduled Task
  │                         │
  │                         ├─ 理解订阅指令
  │                         ├─ 搜索国内外热点
  │                         └─ 准备推送
  ▼
飞书发件箱工作器 ────────▶ 飞书消息 API

本机浏览器 ──▶ 127.0.0.1 管理页面 ──▶ SQLite
```

### 3.1 进程组件

- **长连接客户端**：在独立后台线程中维护飞书 WebSocket 会话。
- **SDK 事件适配器**：把 SDK 事件对象转换为项目内部的标准事件，不让业务层依赖 SDK 数据结构。
- **事件接收器**：执行群聊、文本、机器人提及、自身消息过滤及 SQLite 幂等写入。
- **发件箱工作器**：保持现状，负责固定确认、最终结果和热点卡片的可靠发送。
- **管理服务**：保持只监听 `127.0.0.1`，并增加只读的长连接运行状态。
- **运行时监督器**：统一启动、监控和停止上述组件。

### 3.2 事件数据流

1. 官方 SDK 从长连接接收 `im.message.receive_v1`。
2. 适配器提取 `event_id`、`message_id`、`chat_id`、发送者、消息类型、正文和 mentions。
3. 接收器仅接受群聊文本、非机器人自身消息，并以 mentions 结构确认当前机器人被明确提及。
4. 在同一个 SQLite 事务中写入幂等事件记录和固定确认消息的发件箱记录。
5. 事务提交成功后，事件处理函数向 SDK 返回成功；提交失败则返回失败，使飞书可以重新投递。
6. 后续自然语言理解、订阅变更、搜索与推送继续异步执行。

长连接回调不执行模型调用、网页搜索或飞书出站请求，从而保持快速响应。

## 4. 配置与代理

### 4.1 飞书配置

只保留以下必填凭据：

```dotenv
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
```

移除 webhook 专用配置：

```text
FEISHU_VERIFICATION_TOKEN
FEISHU_ENCRYPT_KEY
FEISHU_CALLBACK_HOST
FEISHU_CALLBACK_PORT
```

配置文件中的 callback server 配置也一并移除。管理页面的监听设置保持不变，并继续强制为 `127.0.0.1`。

### 4.2 代理解析

长连接及其端点发现按以下优先级选择第一个非空值：

```text
FEISHU_WS_PROXY
HTTPS_PROXY
https_proxy
ALL_PROXY
all_proxy
```

当前环境中的 `http://127.0.0.1:7890` 因此会自动生效。需要为 HotNews 单独指定代理时，可以设置：

```dotenv
FEISHU_WS_PROXY=http://127.0.0.1:7890
```

支持 `http`、`https`、`socks5` 和 `socks5h`。空白值视为未配置；其他协议、缺失主机或非法端口在启动时直接报错。SOCKS 支持所需的 PySocks 依赖随项目安装。

`FEISHU_WS_PROXY` 仅覆盖飞书长连接和长连接端点发现。飞书 REST API 与其他 HTTPS 请求继续使用标准代理环境变量，避免项目私有变量意外改变所有外部请求。

### 4.3 脱敏规则

- 不记录 App Secret、代理密码或完整临时 WebSocket URL。
- 代理日志只显示协议、脱敏主机和端口；存在用户名时只显示其已配置。
- SDK 异常在进入日志、管理状态或 CLI 输出前统一清除 URL 查询参数和代理认证信息。
- 管理页面只展示连接状态和脱敏错误，不展示代理原值。

## 5. SDK 兼容层

兼容层是项目中唯一允许接触 SDK 私有长连接接口的模块。它提供稳定的项目内部接口：

```text
build_long_connection(app_id, app_secret, proxy, event_handler)
```

职责包括：

- 验证已安装 SDK 版本位于项目支持范围；
- 验证被适配的连接函数参数仍符合预期；
- 只对当前客户端实例注入代理，不改变其他库或进程的全局网络行为；
- 将 SDK 事件映射到项目内部事件适配器；
- 将连接生命周期通知运行状态存储；
- 在 SDK 不兼容时给出可操作错误，而不是无代理静默直连。

业务模块不得直接引用 SDK 私有成员。后续官方 SDK 提供公开代理接口时，只替换该模块，不改事件、存储或运行时逻辑。

## 6. 故障恢复与一致性

### 6.1 连接生命周期

- 网络或代理短暂中断时自动重连，使用有上限且带随机抖动的指数退避。
- 连接失败不停止管理页面、到期订阅处理或已入库消息的发送。
- 代理恢复后无需人工重启进程。
- 永久鉴权错误或 SDK 不兼容错误标记为致命状态，并使运行时以失败退出，方便用户及时发现配置问题。
- 重复连接错误按时间节流，避免长期断网刷屏。

### 6.2 事件一致性

- SQLite 提交成功后才确认长连接事件成功。
- 数据库失败时让飞书重投；现有 `event_id` 与 `message_id` 幂等约束防止重复处理。
- 重复事件不产生第二条订阅、确认消息或最终回复。
- 一条消息包含多条订阅时分别校验和创建；某条非法内容不回滚其他合法订阅。
- 应用退出时先停止接收新事件，再等待当前数据库事务结束；已落库工作由下次启动继续执行。

### 6.3 运行状态

进程内维护以下非敏感状态，并在管理 API 中只读呈现：

- `starting`、`connected`、`reconnecting`、`stopped` 或 `fatal`；
- 最近一次成功连接时间；
- 最近一次收到事件时间；
- 连续重连次数；
- 最近一次脱敏错误。

状态只用于诊断，不作为业务幂等或调度依据。

## 7. 诊断命令

新增：

```bash
hotnews check-feishu
```

命令按顺序检查：

1. 配置与代理 URL 合法性；
2. App ID 与 App Secret 能否完成鉴权；
3. 能否取得机器人身份；
4. 能否通过所选代理完成长连接端点发现和 WebSocket 握手；
5. 握手成功后主动断开。

诊断不创建订阅、不修改现有订阅、不发送群消息。命令有明确的总超时和非零失败退出码，输出使用统一脱敏规则。

## 8. 删除和迁移

本次不提供双模式或回退开关。将删除：

- webhook HTTP 网关和 callback server；
- URL verification、verification token 校验和 Encrypt Key 解密；
- webhook 路由、监听地址、监听端口及对应测试；
- 文档中的公网域名、端口转发和内网穿透步骤；
- 容器中的 webhook 端口暴露。

现有 SQLite 数据无需迁移。事件表、订阅表、投递历史和发件箱结构继续使用；若连接状态需要持久化字段，应通过正常数据库 migration 添加，不直接修改用户数据库。

飞书开放平台需要把事件订阅方式改为“使用长连接接收事件”，继续订阅 `im.message.receive_v1`，并保持机器人读取群消息与发送消息所需权限。切换完成后，不再配置请求地址。

## 9. 测试策略

所有自动化测试使用假 SDK 客户端和本地测试替身，不依赖真实飞书或外网。

至少覆盖：

- 代理环境变量的优先级、支持协议、非法输入和凭据脱敏；
- SDK 版本及私有接口兼容检查；
- SDK 事件到内部事件的转换；
- 群聊、文本、mentions 和自身消息过滤；
- SQLite 成功或失败时的事件确认行为；
- 重复投递幂等与多条订阅处理；
- 断线重连、退避、代理恢复和优雅停止；
- 管理页面的连接状态与错误脱敏；
- `check-feishu` 的成功、超时、鉴权失败、代理失败和无副作用；
- 配置与运行入口中不再要求或启动 webhook。

完成自动化测试后，再使用用户当前真实代理执行一次只读 `check-feishu`。只有用户已配置真实 App ID 与 App Secret 时才执行该检查；输出不得包含凭据。

## 10. 验收标准

- 应用不监听任何飞书公网回调端口，仍能收到群消息事件。
- 未明确 `@机器人` 的消息不会创建或修改订阅。
- 当前 `127.0.0.1:7890` HTTP 代理可用于端点发现和长连接。
- 代理暂时不可用后恢复，长连接可以自动恢复。
- 飞书重复投递不会创建重复订阅或回复。
- 原有订阅、搜索、推送、SQLite 恢复和本机管理功能继续通过测试。
- 管理页面仍只能从本机访问。
- 代码和文档中不再存在可运行的 webhook 入口。
- 日志、CLI 和管理页面不泄露 App Secret、代理凭据或临时连接 URL。
