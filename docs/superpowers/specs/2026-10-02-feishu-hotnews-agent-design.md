# 飞书热点订阅 Agent 设计规格

日期：2026-10-02  
状态：待用户书面审阅  
设计路径：Superpowers Architectural

## 1. 背景与目标

本项目为个人长期运行的飞书热点订阅 Agent。电脑与 Codex 桌面应用保持在线，群成员通过 `@机器人` 管理群共享的热点订阅。系统尽量复用 Codex 的模型、网页搜索和 Scheduled Tasks，不额外调用 OpenAI API。

首版成功标准：

- 只有飞书群内明确 `@机器人` 的文本消息会被处理。
- 群内任何成员都能创建、查看、立即执行或取消本群订阅。
- 每个群可以拥有多条独立订阅。
- 未指定推送时间时，默认每天 09:00（Asia/Shanghai）。
- Codex 同时搜索国内外公开网页，生成中文摘要并附原文链接。
- 搜索优先覆盖最近 24 小时，不足时依次扩展到 7 天和 30 天。
- 每次最多推送 10 条，不以低相关内容凑数，并避免重复推送。
- 订阅和任务状态持久化，机器或进程重启后可以恢复。
- 提供仅限本机访问的管理页面，可查看、修改和操作已有订阅。

## 2. 范围

### 2.1 首版范围

- 飞书应用事件回调和应用身份消息发送。
- 群聊文本消息与机器人提及检测。
- 自然语言订阅指令理解。
- 群级多订阅与共享管理权限。
- 每日定时、分钟/小时间隔和立即执行。
- Codex Scheduled Task 周期性编排。
- 国内外网页搜索、筛选、中文摘要和飞书推送。
- SQLite 持久化、事件幂等、文章去重、失败恢复和 dry-run。
- 本地订阅管理页面及受限管理 API。

### 2.2 非目标

- 企业微信或个人微信接入。
- 私聊订阅。
- 公网管理后台、用户登录系统或复杂后台权限。
- 多租户隔离、收费、审计审批和复杂角色权限。
- 任意 cron 表达式或秒级准时调度。
- 为每条订阅分别创建 Codex Scheduled Task。
- 通过 Agents API、Responses API 或其他 OpenAI API 调用模型。
- 强行补足固定条数的低相关资讯。

## 3. 总体架构

系统采用“飞书回调网关 + 本地管理服务 + SQLite 状态边界 + 单个 Codex Scheduled Task + 飞书消息 API”的结构。

```text
飞书群 @机器人
      │ im.message.receive_v1
      ▼
飞书回调网关 ───────▶ SQLite ◀─────── Codex Scheduled Task
      │                 │                  │
      │                 │                  ├─理解待处理指令
      │                 │                  ├─领取到期订阅
      │                 │                  ├─搜索国内外网页
      │                 │                  └─生成中文摘要
      │                 │
      └──── 飞书出站队列 ┴──────────────▶ 飞书消息 API ──▶ 原群

本机浏览器 ───────▶ 本地管理服务 ───────▶ SQLite
  127.0.0.1              127.0.0.1
```

### 3.1 飞书回调网关

常驻的轻量 Python 服务，职责仅包括：

- 响应飞书 URL verification。
- 校验 verification token；配置 Encrypt Key 时解密事件。
- 接受 `im.message.receive_v1` 文本事件。
- 确认消息来自群聊、发送者不是机器人自身，且 mentions 中包含当前机器人。
- 使用飞书 `event_id` 和 `message_id` 做幂等。
- 原样保存消息正文、群 ID、发送者 ID、提及信息和接收时间。
- 在数据库提交成功后立即向飞书回调返回 HTTP 200。
- 通过本地短生命周期出站工作器发送固定确认：“已收到，将在 5 分钟内处理。”

网关不理解自然语言，不搜索网页，也不判断订阅是否到期。对外只暴露健康检查与飞书回调端点。

### 3.2 SQLite 状态边界

SQLite 是网关、CLI 和 Codex 之间唯一共享的可变状态。所有写入使用参数化语句和事务。模型不能直接生成或执行 SQL。

### 3.3 Codex Scheduled Task

项目仅维护一个每 5 分钟运行的 Codex Scheduled Task。任务进入本项目目录，显式调用项目内 `hotnews-agent` 技能。每轮运行：

1. 获取全局运行租约；若已有未过期运行则安全退出。
2. 领取一批待处理飞书事件。
3. 将每条自然语言消息转换为受约束的结构化意图。
4. 通过本地 CLI 校验并应用订阅变更，把结果写入飞书出站队列。
5. 领取一批已经到期或被要求立即执行的订阅。
6. 对每条订阅执行网页搜索、筛选、去重、摘要和推送准备。
7. 通过本地 CLI 写入文章、投递和下一次运行状态。
8. 释放租约；未完成任务留给下一轮。

该设计允许 0–5 分钟的指令处理和计划执行延迟。它不承诺分钟边界上的秒级准时。

### 3.4 项目技能与受限 CLI

`hotnews-agent` 技能定义 Codex 的固定工作流、搜索准则、提示注入防护、输出格式和错误处理。CLI 提供窄接口，使用 JSON 输入输出，例如：

- 领取和确认待处理事件。
- 校验并应用结构化意图。
- 列出、领取和完成到期订阅。
- 查询该订阅已经推送的文章标识。
- 准备、完成或失败一次投递。
- 执行 dry-run 并输出预览。

CLI 拒绝未知字段、非法时间、空关键词、跨群订阅编号和无租约的状态变更。

### 3.5 本地管理服务

管理服务与飞书回调网关使用不同监听端口，默认只监听 `127.0.0.1:8081`。它提供项目内置的单页 HTML、少量 CSS、原生 JavaScript 和受限 JSON API，不使用前端框架或构建工具。

管理服务可以查看和操作已有订阅，但不能创建订阅。新增订阅仍必须由飞书群成员 `@机器人` 发起，以保持唯一入口和群上下文完整。

管理服务与飞书指令共享 repository 层和事务规则，不直接拼接 SQL。它不读取、不展示也不修改飞书密钥或应用配置。

## 4. 飞书事件与消息流程

### 4.1 入站过滤

仅处理同时满足以下条件的事件：

- 事件类型为 `im.message.receive_v1`。
- 会话类型为群聊。
- 消息类型为文本。
- mentions 明确包含当前机器人。
- 发送者不是机器人或应用自身。

不依赖正文中是否出现字面量 `@机器人`，以飞书事件中的 mentions 结构为准。过滤后的正文会移除机器人提及文本，但保留用户其余原话。

### 4.2 支持的用户意图

首版支持：

```text
@机器人 订阅 AI Agent 和大模型，每天早上 9 点
@机器人 订阅新能源汽车，每隔 2 小时
@机器人 查看订阅
@机器人 取消订阅 2
@机器人 立即推送 1
@机器人 帮助
```

结构化意图类型为：

- `create_subscription`
- `list_subscriptions`
- `cancel_subscription`
- `run_subscription_now`
- `show_help`
- `clarification_required`

创建意图至少包含关键词。计划缺省为每天 09:00。模型可以生成中英文搜索扩展词，但必须同时保存用户原始关键词，且扩展词不能改变主题含义。

取消、查看和立即执行均以事件所在群为边界。群内任何成员可以操作该群的全部订阅。含义不明确时返回帮助和改写示例，不猜测订阅编号、时间或主题。

### 4.3 确认与最终回复

- 网关在持久化入站事件后发送固定接收确认。
- Codex 应用意图后再发送最终结果，例如订阅编号、关键词和下一次运行时间。
- 重复事件不会产生第二条订阅或第二次最终回复。
- 非法指令不进入订阅表，只返回帮助信息。

### 4.4 管理页面交互

主页面展示订阅表格，包含：

- 群名称；无法读取群名称时显示群 ID。
- 群内订阅编号。
- 订阅主题、原始关键词和搜索词更新状态。
- 调度方式、下一次执行时间和启用状态。
- 最近成功时间、连续失败次数。
- 编辑、暂停/恢复、立即推送和取消操作。

默认隐藏已经取消的订阅，用户可以切换查看历史记录。页面允许筛选群、状态和关键词，但不提供新增入口。

编辑面板允许修改订阅主题、原始关键词和调度方式。保存后立即重算下一次执行时间，保留全部历史推送记录，并且不会自动执行一次推送。用户需要即时结果时使用“立即推送”。

关键词变化时，旧的中英文扩展词立即失效，订阅进入 `search_terms_pending` 状态。下一轮 Codex Scheduled Task 根据新的原始关键词生成扩展词并恢复为 `ready`；在扩展完成前，该订阅不会自动运行，以免使用过期或不完整的搜索词。管理页明确显示“等待 Codex 更新搜索词”。

管理 API 为：

```text
GET    /api/subscriptions
GET    /api/subscriptions/{id}
PATCH  /api/subscriptions/{id}
POST   /api/subscriptions/{id}/pause
POST   /api/subscriptions/{id}/resume
POST   /api/subscriptions/{id}/run-now
DELETE /api/subscriptions/{id}
```

所有修改操作要求提交当前 `version`。如果订阅已被飞书指令、Codex 或另一个页面修改，服务返回 HTTP 409，页面要求刷新后重新编辑，不静默覆盖。

## 5. 订阅与调度语义

### 5.1 订阅标识

每条订阅有内部 UUID 和群内递增展示编号。用户通过展示编号管理订阅。取消采用软删除，展示编号不复用。

### 5.2 支持的计划

- `daily`：每天本地时间 `HH:MM`。
- `interval`：每隔 N 分钟或 N 小时，最小间隔 5 分钟。
- `manual`：由“立即推送”产生的一次性运行，不改变原计划。

统一时区为 `Asia/Shanghai`。`next_run_at` 以 UTC 时间戳持久化，展示时转换为本地时间。

如果机器离线导致计划错过，恢复后的第一轮只补执行一次，不为每个错过的周期分别补发。成功完成后从当前时间计算下一次间隔任务；每日任务计算下一个本地计划时间。

暂停订阅时保留 `next_run_at` 供展示，但不会被到期查询领取；恢复时从恢复时间重新计算下一次执行时间。管理页“立即推送”只创建一次手动运行，不会隐式恢复暂停订阅，也不改变其正常计划。

## 6. 热点搜索与筛选

### 6.1 搜索范围

每条订阅独立搜索：

1. 使用原始关键词和不改变语义的中英文扩展词检索最近 24 小时。
2. 合格结果不足 10 条时，将范围扩展到最近 7 天。
3. 仍不足时扩展到最近 30 天。
4. 达到 10 条或 30 天边界后停止。

搜索覆盖国内外可公开访问网页。优先级依次考虑官方公告、公司或机构博客、论文与研究机构、主流新闻机构、可信行业媒体。搜索结果页和聚合页可以用于发现线索，但最终链接应尽量指向原始来源。

### 6.2 选择标准

候选内容按以下因素综合排序：

- 与订阅关键词的直接相关性。
- 原始发布时间。
- 来源可信度和是否为一手来源。
- 是否得到多个相互独立来源印证。
- 是否提供新的事实，而非重复转载或轻微改写。

最多选择 10 条。没有足够合格内容时少发；30 天内没有合适且未推送内容时保持安静。

### 6.3 去重

去重分两层：

- 确定性去重：规范化 URL 后计算哈希，移除跟踪参数和无意义片段。
- 事件级去重：标题和事实高度相似的多篇报道合并为一条，选择最权威来源作为主链接，其余来源作为交叉参考。

投递历史按订阅记录。取消后重新创建相同主题不会清除历史文章标识，从而避免立即重发旧内容。

### 6.4 提示注入防护

网页内容全部是不可信资料。页面中的指令、角色声明、工具调用要求、密钥请求或“忽略之前规则”等文本不得改变技能工作流。Codex 只提取与热点事实有关的信息，不执行网页要求的命令，不读取或披露本地密钥。

## 7. 推送格式

每次推送使用飞书消息卡片，卡片头部包含订阅编号、原始关键词和本次检索窗口。每条资讯包含：

- 标题。
- 2–3 句中文摘要。
- 来源名称。
- 原始发布日期；无法可靠确认日期的内容不入选。
- 原文链接。
- 有必要时附 1–2 个交叉参考来源。

超过最近 24 小时的内容标注“历史补充”，并显示明确日期。国外内容用中文摘要，标题可以保留原文并附简短中文释义。

只有飞书 API 明确返回成功后，才将该批文章标记为已推送。网络失败、限流或鉴权失败时保留出站记录并重试，不提前写入成功历史。

## 8. 数据模型

核心表及职责如下：

### `inbound_events`

- 飞书事件 ID、消息 ID、群 ID、发送者 ID。
- 原始文本、去除机器人 mention 后的文本、接收时间。
- `pending / leased / completed / failed` 状态。
- 租约截止时间、尝试次数、最后错误和处理结果摘要。

### `subscriptions`

- 内部 UUID、群 ID、群内展示编号、创建者 ID。
- 原始关键词和中英文扩展词 JSON。
- 计划类型、计划参数、时区、下一次运行时间。
- `ready / search_terms_pending / paused / cancelled` 状态。
- 乐观并发版本号、创建/更新时间、取消时间。
- 最近成功时间、连续失败次数和最近告警时间。

### `subscription_runs`

- 运行 ID、订阅 ID、触发方式、搜索窗口和状态。
- 租约信息、开始/完成时间、错误和候选/入选数量。

### `articles`

- 规范化 URL 哈希、标题、主链接、来源、发布日期。
- 摘要、交叉来源和首次发现时间。

### `deliveries`

- 订阅 ID、文章 ID、运行 ID、飞书消息 ID和投递状态。
- 尝试次数、成功时间和最后错误。

### `outbox`

- 目标群、消息类型、结构化内容、状态、租约和重试信息。
- 同一业务动作的幂等键，防止确认或摘要重复发送。

### `agent_leases`

- 全局 Codex 运行锁和工作项租约，包含拥有者与过期时间。

数据库启用 WAL、busy timeout 和外键约束。迁移使用显式 schema version，启动时只执行前向迁移。

## 9. 可靠性与错误处理

- Codex 每轮先获取全局租约，避免 Scheduled Task 重叠运行。
- 工作项采用“领取—执行—确认”流程；租约过期后可重领。
- 单轮设置最大事件数、最大订阅数和软时间预算，未处理项留到下一轮。
- 鉴权失败时刷新一次飞书 tenant access token 后重试。
- 飞书限流遵守返回信息退避，网络错误采用有限指数退避。
- 单条订阅失败不影响其他订阅。
- 连续失败达到阈值后只发送一次异常提醒；恢复成功后清零计数。
- 没有合格热点不是错误，不发送空卡片，也不增加失败计数。
- dry-run 执行完整的读取、搜索、筛选和卡片渲染，但不调用发送接口，也不写成功投递历史。

## 10. 安全与配置

- `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_VERIFICATION_TOKEN` 和可选 `FEISHU_ENCRYPT_KEY` 仅从环境变量读取。
- 密钥不写入配置样例、SQLite、日志、技能文件、Codex prompt 或错误回执。
- 日志对 URL 查询参数、Authorization 头和消息正文进行必要脱敏。
- 回调请求限制正文大小，只接受 JSON，并设置读取和处理超时。
- 对外 HTTPS 由 Cloudflare Tunnel、反向代理或等价方案提供；应用自身仅监听本机或受信任接口。
- 本地 CLI 只允许预定义动作和严格 JSON schema，不接受任意 shell 或 SQL 字符串。
- 管理服务强制绑定 `127.0.0.1`，并拒绝非 `localhost` 或 `127.0.0.1` 的 Host。
- 管理 API 的修改请求校验同源 Origin 和会话级 CSRF token，降低恶意网页调用本地接口的风险。
- 页面所有动态内容均使用安全 DOM API 或 HTML 转义，群名称、主题和关键词不得作为原始 HTML 注入。

## 11. 项目结构边界

目标结构按职责拆分：

```text
src/hotnews/
  feishu/        # 回调协议、事件标准化、token 与消息发送
  storage/       # schema、迁移、repositories、租约和事务
  commands/      # 结构化意图 schema 与订阅操作
  delivery/      # 卡片渲染、outbox 和投递状态机
  admin/         # 仅本机管理服务、JSON API 和静态页面
  cli.py         # Codex 可调用的窄 JSON 接口
skills/
  hotnews-agent/
    SKILL.md      # 搜索、筛选、摘要和状态流工作法
tests/
  unit/
  integration/
```

现有代码的处理原则：

- 移除企业微信配置、回调、加解密、渠道和文档。
- 移除进程内无限调度循环。
- 将每群单条动态订阅存储替换为群内多订阅模型。
- 将正则表达式主解析器替换为 Codex 结构化意图；保留确定性的 schema 校验。
- 复用经过测试仍符合边界的飞书 API、SQLite 和消息渲染逻辑。
- RSS、Atom 和 Hacker News 采集器不进入首版主流程；全网搜索由 Codex 完成。
- 管理页面使用原生 HTML、CSS 和 JavaScript，不引入前端打包工具或 SPA 框架。

## 12. 测试与验收

### 12.1 自动化测试

- 意图 schema：合法动作、未知字段、缺失关键词、非法编号和非法时间。
- 订阅：群内多条、编号不复用、默认 09:00、软删除和跨群隔离。
- 调度：每日、间隔、立即执行、离线补执行一次和时区转换。
- 入站：URL verification、明文/加密事件、mention 过滤、自身消息过滤和事件幂等。
- 状态机：租约领取、过期恢复、重复确认和并发写入。
- 搜索结果契约：时间窗口、发布日期必填、最多 10 条和重复合并。
- 投递：成功、限流、token 失效刷新、网络失败和 outbox 重试。
- 安全：提示注入样例、日志脱敏和非法 CLI 输入。
- 管理端：列表、筛选、修改、版本冲突、暂停/恢复、立即推送、软删除、Host/Origin/CSRF 校验和 XSS 转义。

自动化测试不依赖真实网页搜索或真实飞书网络；外部边界使用固定样例和 mock。

### 12.2 手工验收

在测试飞书群完成：

1. 连续创建两条不同计划的订阅并获得不同编号。
2. 查看列表，确认关键词、计划和下一次执行时间正确。
3. 由另一名群成员立即执行其中一条。
4. 确认国内外来源、中文摘要、日期、原文链接和历史补充标记。
5. 重复投递同一飞书事件，确认不重复创建。
6. 重启网关和 Codex 桌面应用，确认订阅与到期状态恢复。
7. 取消其中一条，确认另一条不受影响且取消编号不复用。
8. 模拟一次发送失败，确认下轮重试且不会产生重复成功记录。
9. 运行 dry-run，确认产生预览但不发送、不写成功投递。
10. 在本机管理页修改一条订阅的关键词和时间，确认版本递增、历史投递保留、搜索词进入待更新状态且下轮 Codex 正确恢复。
11. 验证暂停、恢复、立即推送、软删除和并发修改冲突行为。
12. 从非本机 Host 或跨 Origin 发起管理请求，确认被拒绝。

## 13. 部署与运维

- 本地网关作为系统服务或容器长期运行。
- 本地管理服务随网关进程启动，但单独绑定 `127.0.0.1:8081`；公网 Tunnel 和反向代理不得转发该端口。
- SQLite 文件放在持久化目录并定期备份。
- 公网 HTTPS 回调转发到网关；健康检查端点不暴露敏感状态。
- Codex 桌面端创建一个每 5 分钟执行的项目 Scheduled Task，prompt 固定要求显式调用 `hotnews-agent` 技能。
- 首次上线前在普通 Codex 对话中 dry-run 同一技能工作流，确认权限和网页搜索可用。
- 运行日志记录关联 ID、状态和耗时，不记录密钥或完整敏感正文。

## 14. 已接受的权衡

- 以 0–5 分钟响应延迟换取不调用额外模型 API 和更低维护成本。
- 使用一个轮询型 Scheduled Task，而不是为动态订阅创建多个任务。
- 任何群成员均可管理群共享订阅，不实现管理员角色。
- 以 Codex 网页搜索代替固定 RSS 来源，获得国内外覆盖，但结果数量和站点可访问性可能随运行环境变化。
- 最多回溯 30 天；超过 24 小时的结果必须显式标注，避免把历史内容表现为即时新闻。
- 以仅本机、无登录的管理页面换取更低部署复杂度，并通过监听地址、Host、Origin 和 CSRF 校验维持本地安全边界。
